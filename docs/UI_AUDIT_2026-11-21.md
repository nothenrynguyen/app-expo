## Detailed findings

### 1. [P1] Outgoing results remain interactive and obscure the reduced-motion view

- Location: `app/job-board/JobResults.tsx:85`, `app/job-board.css:171`, `app/job-board.css:405`, `app/JobBoard.tsx:81`, `app/job-board/job-board-utils.ts:5`.
- Category: Accessibility / Implementation integrity.
- Evidence: both outgoing and incoming result trees are mounted. Outgoing panels disable pointer events but have no `inert` or accessibility-tree exclusion. The outgoing panel has a higher z-index. Reduced-motion CSS disables animation and clears clipping on both panels, while JavaScript still waits 1,050ms to remove the outgoing panel.
- Impact: keyboard traversal can reach duplicate, visually hidden actions. Reduced-motion users can see the old layout covering the new one while clicks pass through to the new controls.
- Standard: focus-order/visible-focus risk (WCAG 2.4.3 and 2.4.7); browser verification should establish the exact exposed behavior.
- Recommendation: make the outgoing tree inert and hidden from assistive technology, preserve sensible focus when changing layout, and bypass the outgoing transition entirely for reduced motion.
- Suggested command: `$impeccable harden`, followed by `$impeccable animate` for transition behavior.

### 2. [P1] Filter disclosures omit their visible field labels from accessible names

- Location: `app/job-board/JobFilters.tsx:211` and `app/job-board/JobFilters.tsx:245`.
- Category: Accessibility.
- Evidence: Location, Metro area, Workplace, Term, Specialty, and Company tier headings are sibling spans. The summaries contain only the selected value, often "All". No heading ID or `aria-labelledby` connects the field name to the summary. Multi-filter checkbox sets also lack a named group.
- Impact: users navigating controls with a screen reader cannot reliably distinguish several "All" disclosures or identify the group of repeated all-options.
- Standard: WCAG 1.3.1 and 2.4.6 concerns.
- Recommendation: name each summary with its field label and selected value, and use named fieldsets or groups for option sets. Preserve the search input's existing wrapping label.
- Suggested command: `$impeccable harden`.

### 3. [P1] Job-result status changes are not announced

- Location: `app/JobBoard.tsx:121`, `app/JobBoard.tsx:169`, `app/JobBoard.tsx:207`.
- Category: Accessibility.
- Evidence: loading/error paragraphs, the matching-role count, and pagination text lack a live status mechanism. Query and checkbox handlers change results without moving focus or announcing the resulting count. Storage-error alerts and the hidden-company status already use explicit roles, so those are not part of this finding.
- Impact: a screen-reader user can change filters without learning whether any matches remain, or change page without a concise completion cue.
- Standard: WCAG 4.1.3, particularly the dynamic search-result count.
- Recommendation: add a concise polite status for settled result count/page changes and appropriate loading/error state announcements. Avoid announcing the whole result list or every keystroke without debouncing.
- Suggested command: `$impeccable harden`.

### 4. [P1] Full-location tooltip lacks dismissal and stable hover access

- Location: `app/job-board/JobResults.tsx:128`, `app/job-board.css:229`.
- Category: Accessibility.
- Evidence: full locations appear on hover or focus through CSS. The tooltip has `pointer-events:none`, no Escape handler, and no `aria-describedby` relationship. Moving from the compact text into a portion of the popover outside its trigger cannot reliably preserve the hover state.
- Impact: long location information can disappear while a magnifier or pointer user tries to read it; keyboard users cannot dismiss overlapping content without leaving the trigger.
- Standard: WCAG 1.4.13 concerns for dismissible and hoverable supplemental content.
- Recommendation: use a stable hover/focus region with Escape dismissal and a programmatic description, or expose the complete location in an explicit disclosure that also works on touch.
- Suggested command: `$impeccable harden`.

### 5. [P2] Specialty links advertise radio behavior without implementing it

- Location: `app/job-board/JobFilters.tsx:219`.
- Category: Accessibility / Implementation integrity.
- Evidence: Next links receive `role="radio"` inside `role="radiogroup"`, but no arrow-key selection or roving tab stop is implemented. Every link remains independently tabbable.
- Impact: the announced widget type promises keyboard behavior that the control does not provide. Enter navigation still offers a workaround.
- Standard: ARIA radio-group keyboard-pattern mismatch; not independently classified here as a proven WCAG keyboard failure because the links remain operable.
- Recommendation: retain link semantics and mark the active destination, or implement a complete native/custom radio group with deliberate navigation behavior.
- Suggested command: `$impeccable harden`.

### 6. [P2] Small targets remain in card actions and company menus

- Location: `app/job-board.css:186`, `app/job-board.css:424`, `app/globals.css:230`.
- Category: Responsive design.
- Evidence: general card action buttons have a 37px minimum height; company-action summaries are explicitly 24 by 32px; tracker status selects have a 31px minimum height. Mobile compact Save/Apply controls and filter options already increase to 44px, but the general card actions and company-action summary do not receive equivalent overrides.
- Impact: adjacent actions demand more precise touch input, especially in card view or company hiding.
- Standard: below the audit's 44px touch target goal. This alone does not establish a WCAG 2.5.8 AA failure, which has a different minimum and exceptions.
- Recommendation: extend the existing mobile 44px target convention to card actions, company summaries, and tracker controls without reducing information density on pointer devices.
- Suggested command: `$impeccable adapt`.

### 7. [P2] Closing the application editor removes the focused control without restoring focus

- Location: `app/applications/ApplicationTracker.tsx:23`, `app/applications/ApplicationTracker.tsx:51`, `app/applications/ApplicationTracker.tsx:61`, `app/applications/ApplicationTracker.tsx:65`.
- Category: Accessibility.
- Evidence: opening the editor deliberately focuses its first input. Save, Cancel, and Delete unmount the editor with no corresponding focus restoration.
- Impact: keyboard users lose their place after editing a record. The status message announces the outcome, but it does not restore a useful navigation position.
- Standard: focus-management concern related to WCAG 2.4.3; confirm exact browser focus fallback during verification.
- Recommendation: retain the invoking control and restore focus after closing. If deletion removes the invoker, focus a nearby record action or Add application.
- Suggested command: `$impeccable harden`.

### 8. [P2] Repeated dark surfaces bypass shared tokens

- Location: `app/globals.css:1`, `app/job-board.css:100`, `app/job-board.css:136`, `app/job-board.css:188`, `app/job-board.css:334`.
- Category: Theming.
- Evidence: shared semantic tokens exist, but filter inputs, menus, secondary actions, and the mobile panel repeat literal backgrounds/borders such as `#191a1f`, `#202126`, and `#3a3b45`.
- Impact: a contrast or surface adjustment requires editing several independent selectors and can leave closely related controls inconsistent.
- Standard: maintainability issue, not a demonstrated contrast failure.
- Recommendation: introduce narrowly named input/menu/secondary-action tokens and replace repeated semantic literals. Preserve intentional decorative colors and status-specific hues.
- Suggested command: `$impeccable polish`.

## Patterns and positive findings

The main recurring gap is incomplete state semantics: disclosure labels, radio roles, status announcements, and outgoing transition controls each diverge from otherwise intentional visual behavior. Mobile target sizing is handled for core compact actions but not consistently across alternate views. Surface tokens are established, so this needs a bounded cleanup rather than a theme replacement.

Preserve these strengths:

- Search and tracker form inputs have wrapping labels; saved controls include the job title/company and pressed state.
- Mobile filters implement Escape, first-focus placement, Tab wrapping, focus return, a scrollable panel, and larger filter controls.
- Reduced-motion support provides static headline/count alternatives, stops gravity interactions, and removes decorative save animations. The transition defect is specific, not evidence that all reduced-motion handling is absent.
- Pagination limits rendered listings to 100. Filtering and derived option lists use memoization. Gravity drawing is scheduled on demand and device-pixel-ratio scaling is capped.
- Snapshot polling avoids hidden-page requests and overlapping refreshes, reads the lightweight summary before replacing an existing snapshot, and retains successful data during later failures.
- Logo images have explicit dimensions and empty alternative text inside a decorative wrapper.
- Application records use a captioned native table, named status selects, explicit empty states, and live save/error feedback.
- Dark mode is the established sole theme. Missing light mode is not a defect. No rendered contrast failure is claimed from source inspection alone.
